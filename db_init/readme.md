# Database Initialization (db-init)

This folder contains SQL scripts used to initialize the PostgreSQL database
for the **IoT Fire Detection and Safety System**.

The scripts in this directory are automatically executed when the PostgreSQL
Docker container is started for the first time.

---

## init.sql

### Purpose
`init.sql` is responsible for:
- creating the database schema
- creating required tables
- preparing the database for backend services

---

## What init.sql does

### 1. Creates schema

```sql
CREATE SCHEMA IF NOT EXISTS iot;


All project tables are stored inside the iot schema to keep the database
organized and avoid conflicts with default PostgreSQL tables.

2. Creates telemetry table
CREATE TABLE IF NOT EXISTS iot.telemetry (
    id SERIAL PRIMARY KEY,
    temperature FLOAT NOT NULL,
    smoke FLOAT NOT NULL,
    flame BOOLEAN NOT NULL,
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);


Purpose:
Stores sensor data sent from IoT devices or simulators.

Columns:

temperature — measured temperature value

smoke — smoke level

flame — flame detection flag

timestamp — time when data was received

3. Creates alarms table
CREATE TABLE IF NOT EXISTS iot.alarms (
    id SERIAL PRIMARY KEY,
    message TEXT NOT NULL,
    level VARCHAR(20),
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);


Purpose:
Stores alarm events generated by the backend when dangerous conditions
are detected.

Columns:

message — alarm description

level — alarm severity (e.g. WARNING, CRITICAL)

timestamp — time when the alarm was created

How it is used

The init.sql script is mounted into the PostgreSQL container

PostgreSQL automatically executes it on first startup

If the database volume already exists, the script will NOT run again

Re-running initialization

To re-run init.sql from scratch:

docker compose down -v
docker compose up -d


⚠️ This will remove all existing database data.
