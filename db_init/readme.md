# Database Initialization

(`db-init`)

This folder contains SQL scripts used to initialize the **PostgreSQL database**
for the **IoT Fire Detection and Safety System**.

The scripts in this directory are executed **automatically** when the PostgreSQL
Docker container is started **for the first time**.

---

## 📄 Files

### `init.sql`

Main database initialization script.

---

## 🎯 Purpose

`init.sql` is responsible for:

- Creating the database schema
- Creating required tables
- Preparing the database for backend services

---

## ⚙️ What `init.sql` Does

### 1️⃣ Creates schema

```sql
CREATE SCHEMA IF NOT EXISTS iot;
```

All project tables are stored inside the `iot` schema to keep the database
organized and separated from default PostgreSQL tables.

---

### 2️⃣ Creates `telemetry` table

```sql
CREATE TABLE IF NOT EXISTS iot.telemetry (
    id SERIAL PRIMARY KEY,
    temperature FLOAT NOT NULL,
    smoke FLOAT NOT NULL,
    flame BOOLEAN NOT NULL,
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**Purpose:**
Stores sensor data sent from IoT devices or the simulator.

**Columns:**

- `temperature` — measured temperature value
- `smoke` — smoke level
- `flame` — flame detection flag
- `timestamp` — time when data was received

---

### 3️⃣ Creates `alarms` table

```sql
CREATE TABLE IF NOT EXISTS iot.alarms (
    id SERIAL PRIMARY KEY,
    message TEXT NOT NULL,
    level VARCHAR(20),
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

**Purpose:**
Stores alarm events generated by the backend when dangerous conditions are detected.

**Columns:**

- `message` — alarm description
- `level` — alarm severity (e.g. `WARNING`, `CRITICAL`)
- `timestamp` — time when the alarm was created

---

## 🐳 How It Works with Docker

- `init.sql` is mounted into the PostgreSQL container
- PostgreSQL executes it automatically **only on first startup**
- If the database volume already exists, the script **will NOT run again**

---

## 🔁 Re-running Initialization

To reset the database and re-run `init.sql` from scratch:

```bash
docker compose down -v
docker compose up -d
```

⚠️ **Warning:**
This will remove **all existing database data**.

---

## ℹ️ Notes

- Do not store secrets or credentials in SQL files
- Use environment variables (`.env`) for configuration
- Modify `init.sql` only when the database structure changes
